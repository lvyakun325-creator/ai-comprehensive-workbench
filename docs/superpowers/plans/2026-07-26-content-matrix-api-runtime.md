# 内容矩阵 Agent 独立 API 运行实施计划

## 目标

在不影响总控台和其他 8 个 Agent 的前提下，为「内容矩阵 Agent」增加独立 API 配置、连接测试和分阶段运行闭环，使用户完成矩阵诊断后，可以调用自己配置的大模型生成战略、战术、执行 SOP 和正式方案。

## Global Constraints

- 所有新增功能只由 `agent.id === "content-matrix"` 消费；其他 8 个 Agent、全局模型配置及总控逻辑保持不变。
- API Key 只存在于当前 `AgentWorkspace` 组件内存中；禁止写入 localStorage、sessionStorage、Cookie、数据库、环境文件、日志、错误文本、响应体或 Git。
- 页面刷新、离开内容矩阵 Agent 或关闭页面后，API Key 必须丢失；配置状态必须明确说明这一点。
- 服务端仅做代理：收到 Key 后立即调用指定模型，不保存、不回显、不记录；所有响应必须设置 `Cache-Control: no-store`。
- 支持三种协议：
  - `openai-compatible`：Bearer 鉴权，`GET /models`，`POST /chat/completions`；
  - `anthropic`：`x-api-key` + `anthropic-version: 2023-06-01`，`GET /models`，`POST /messages`；
  - `gemini`：`x-goog-api-key`，`GET /models`，`POST /models/{model}:generateContent`。
- 提供常用服务商预设，但允许填写自定义 HTTPS 公网接口地址；拒绝 HTTP、localhost、`.local` 和字面量私网/链路本地地址，防止 SSRF。
- API 请求必须有超时、请求体长度和历史阶段数量限制；供应商错误只能返回脱敏后的状态分类，不得透传可能包含敏感信息的响应正文。
- 连接测试只调用模型列表接口，不调用付费生成；模型不存在时给出明确提醒，但不得泄露模型列表之外的供应商响应。
- 严格执行已安装 `matrix-designer` 的阶段顺序：
  1. 用户先完成结构化诊断；
  2. 生成第二阶段“战略判断”，停下等待确认；
  3. 确认后生成第三阶段“账号分层与人设包装”，停下等待确认；
  4. 确认后生成第四阶段“内容裂变与起号 SOP”，停下等待确认；
  5. 确认后生成第五阶段结论先行正式方案。
- 诊断资料、竞品文本、阶段输出和用户修改意见一律按“不可信数据”处理，不能覆盖系统规则或要求泄露配置。
- 强监管行业继续执行医药健康边界：不诊断、不承诺疗效、不诱导停换药、不使用绝对化表达，平台合规优先。
- 最终成品仅在第五阶段提供 Markdown 下载；中间阶段保留确认点，最终文档删除确认话术和过程提示。
- 采用 TDD：每个生产行为先有真实失败测试，再写最小实现。
- 保持现有视觉语言、响应式布局、键盘可访问性和现有 20 项测试。

## Task 1：建立安全的内容矩阵模型运行服务

1. 新增内容矩阵运行核心，负责：
   - 校验协议、接口地址、模型、Key、阶段、诊断资料、历史输出和反馈；
   - 构建三种供应商的连接测试请求与生成请求；
   - 拼装 `matrix-designer` 阶段提示词与不可信数据边界；
   - 解析三种响应格式；
   - 将供应商错误映射为脱敏错误码和中文提示；
   - 强制超时、输入上限、历史阶段上限和 `no-store`。
2. 新增 `POST /api/agents/content-matrix`：
   - `action: "test"` 只测试模型列表；
   - `action: "run"` 运行指定阶段；
   - 成功只返回必要的连接信息或阶段 Markdown；
   - 失败不得回显 Key、供应商响应正文或完整请求。
3. 添加真实核心/路由测试，覆盖：
   - 三种协议的 URL、鉴权头、请求体及响应解析；
   - 自定义接口 SSRF 拒绝；
   - 无效阶段、超长输入、历史越界；
   - 超时、401、429、5xx 和畸形响应的脱敏错误；
   - `Cache-Control: no-store`；
   - 系统提示包含阶段边界、合规边界和不可信数据规则。
4. 提交：`feat: add content matrix model runtime`

## Task 2：接入独立 API 配置与五阶段运行界面

1. 仅为内容矩阵 Agent 的“Agent 配置”标签提供真实配置页：
   - 协议/服务商预设；
   - API 地址；
   - API Key 密码框；
   - 模型名称；
   - “测试连接”和“应用到当前会话”；
   - 明确说明 Key 仅在当前页面内存中、刷新即清空、请求会经过工作台服务端代理。
2. Key 不得出现在 DOM 文本、提示、错误、属性、浏览器存储或调试日志；密码框只显示浏览器原生掩码。
3. 配置成功后，在内容矩阵诊断页显示当前模型状态；未配置时提供直达“Agent 配置”的入口。
4. 诊断完整后提供阶段运行：
   - “开始战略分析”；
   - 第二、三、四阶段输出后显示修改意见输入和人工确认按钮；
   - 第五阶段显示正式 Markdown 与下载按钮；
   - 运行中禁止重复提交；失败后保留已完成阶段，可安全重试；
   - 修改 API 配置后，不把旧 Key或旧供应商信息写入输出。
5. 提供清空当前会话配置按钮；清空后不可继续调用，既有非敏感阶段结果可保留。
6. 添加真实 React 交互测试，覆盖：
   - 内容矩阵专属配置入口及其他 Agent 隔离；
   - 密码框、临时保存、连接测试成功/失败；
   - 未配置时不能运行；
   - 诊断完成后按顺序运行四次模型阶段并显示三个确认点；
   - 错误重试与按钮防重复；
   - 第五阶段 Markdown 下载入口；
   - 清空配置后运行被阻止；
   - 不访问 localStorage/sessionStorage。
7. 运行定向测试、全量 `npm test`、`npm run lint`、`git diff --check`，提交：
   `feat: run content matrix agent with custom api`

# 内容矩阵 Agent 工作台预览实施计划

## 目标

把已安装的 `matrix-designer` 技能填充到「内容矩阵 Agent」工作台，形成一个可以进入、填写和验证的第一阶段诊断闭环，用于判断产品可行性。

## Global Constraints

- 只实现 `content-matrix`，不得改变其他 8 个 Agent 的现有页面与行为。
- 不接入真实大模型、API、数据库或持久化，不伪装为已经生成完整矩阵方案。
- 遵循已安装技能的流程铁律：第一步必须先完成结构化诊断，不能直接输出方案。
- 内容矩阵项目继续保持独立隔离；所有新增能力仅由 `agent.id === "content-matrix"` 消费。
- 医药健康场景保留强监管提示，不提供诊断、疗效承诺或规避平台审核的表达。
- 采用 TDD：先新增真实交互测试并确认因功能缺失而失败，再写最小实现使其通过。
- 保持现有视觉语言、响应式布局、键盘可访问性和现有 17 项测试行为。

## Task 1：实现内容矩阵 Agent 的诊断预览闭环

1. 在内容矩阵项目总览中展示：
   - `matrix-designer` 已安装状态；
   - 五阶段流程，其中当前阶段是“需求澄清”；
   - “开始矩阵诊断”入口。
2. 仅在内容矩阵 Agent 的“Agent 对话”标签中展示结构化诊断表。表单覆盖技能第一阶段的关键输入：
   - 主攻平台；
   - 产品/服务描述；
   - 地域属性；
   - 终极转化；
   - 决策者与使用者是否分离；
   - 客户核心顾虑；
   - 人力与预算；
   - 核心 IP；
   - 账号归属；
   - 当前矩阵阶段；
   - 竞品阵型；
   - 竞品名称、简介、爆款标题（允许选填）；
   - 行业风控；
   - 私域资产（视频号场景重点提示）。
3. 页面实时显示必填信息完成度。
4. 信息未齐时，“提交诊断”不能进入下一阶段，并明确列出仍缺少的栏目。
5. 信息齐全时，提交只显示“诊断资料已就绪，等待下一阶段接入模型进行战略分析”，不得生成虚假方案。
6. 其他标签继续保持现有设计预览行为；Agent 配置保持现有独立模型配置。
7. 添加真实 React 交互测试，至少覆盖：
   - 内容矩阵总览能看到已安装技能及开始入口；
   - 点击入口进入诊断表；
   - 未完成提交会显示缺项；
   - 填完必填项后显示资料已就绪；
   - 竞品洞察 Agent 不显示内容矩阵诊断表。
8. 运行定向测试、全量 `npm test`、`npm run lint` 和 `git diff --check`，提交所有改动。

# AI 综合工作台：单一聊天智能体与模型配置设计

日期：2026-07-27  
状态：用户已确认方案  
本阶段范围：改造首页聊天窗口和模型配置交互，不接入真实模型 API，不保存 API 密钥。

## 1. 目标

将首页聊天窗口从“总控 Agent”调整为一个普通聊天智能体。聊天窗口不负责拆解、调度、分配或管理子 Agent，只负责使用用户当前选择的模型进行一对一对话。

模型列表不再由聊天窗口单独写死。“模型配置”是唯一模型来源：用户在配置中添加并启用模型后，该模型才会出现在聊天窗口的模型下拉列表中。

## 2. 首页聊天窗口

- 角色名称统一为“聊天智能体”。
- 辅助说明改为“选择模型后，直接描述你想完成的事情”。
- 保留输入框、附件入口、工具入口、语音入口和发送按钮。
- 删除“总控 Agent”“拆解并分配”“最大并发”“子 Agent”等总控调度表达。
- 保留模型下拉框，显示当前选中的模型。
- 下拉框仅展示模型配置中处于启用状态的模型。
- 下拉框保留“添加模型”入口，点击后打开模型配置面板。

## 3. 模型配置

模型配置使用浏览器本地存储，作为当前版本唯一的数据源。

每个模型包含：

- 唯一标识。
- 服务商名称。
- 模型显示名称。
- 模型 ID。
- 是否启用。
- 是否为默认模型。

配置面板支持：

- 添加模型。
- 启用或停用模型。
- 设置默认模型。
- 删除模型。
- 查看已配置模型列表。

初始状态保留一个可演示模型，避免首次打开时聊天窗口完全不可用。用户后续可以停用或删除该模型。

## 4. 状态规则

1. 聊天窗口只读取已启用模型。
2. 首次进入时优先选择默认模型。
3. 当前模型被停用或删除时，自动切换到默认的已启用模型。
4. 如果默认模型不可用，则选择第一个已启用模型。
5. 如果没有任何已启用模型，模型选择显示“请先添加模型”，发送按钮禁用。
6. 新增并启用模型后，它立即出现在聊天窗口模型列表中。
7. 同一时间只能有一个默认模型。
8. 配置写入浏览器本地存储，刷新页面后保留。

## 5. 数据与安全边界

- 当前版本不接入真实模型调用。
- 当前版本不要求、不读取、不存储 API 密钥。
- 不把令牌、密码或其他凭据写入浏览器本地存储。
- 发送按钮继续提示“模型能力尚未接入”，避免造成已经可以真实对话的误解。
- 后续接入真实模型时，密钥必须由服务端安全保存，聊天页面只能使用服务端提供的模型配置摘要。

## 6. 测试与验收

- 页面中不再出现总控调度相关文案。
- 页面显示“聊天智能体”。
- 模型配置可以添加模型。
- 已启用模型出现在聊天下拉框中，停用模型不出现。
- 默认模型和回退选择规则正确。
- 没有可用模型时发送按钮不可用，并给出配置提示。
- 刷新页面后模型配置仍然存在。
- 桌面端和移动端布局不出现明显溢出。
- 现有九个核心工作台入口保持不变。

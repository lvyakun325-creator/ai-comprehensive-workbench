# 竞品洞察 Agent：抓取任务与成果文件持久化设计

- 日期：2026-08-01
- 状态：用户已确认，进入实施
- 适用范围：AI 综合工作台的竞品洞察 Agent
- 首期平台：抖音、小红书
- 覆盖关系：本设计仅在竞品洞察 Agent 内覆盖 `2026-07-28-agent-project-task-results-design.md` 中“成果文件只收录 Markdown”的旧限制；其他 Agent 暂时保持原行为。

## 1. 目标

把竞品抓取从“页面发起、文件落盘后流程结束”升级为可追踪、可恢复、可定位成果的完整任务闭环：

1. 用户点击“抓取并分析”后，抓取链接立即出现在竞品洞察 Agent 的任务列表。
2. 任务状态随抓取过程更新，并在刷新网页、关闭浏览器后继续保留。
3. 抓取成功后，将本次生成的 Excel、Markdown、JSON、图片目录和完整输出目录登记为成果。
4. 页面自动切换到“成果文件”，并聚焦本次任务。
5. 用户可以复制成果路径，或通过受控本地接口在 macOS 访达中显示成果。

本期不改变抖音、小红书 Skill 的平台登录态、抓取规则和输出内容，也不把本地任务记录或文件上传到云端。

## 2. 方案选择

采用“本地报告桥统一持久化 + 前端任务/成果动态加载”的方案。

| 方案 | 结论 | 原因 |
|---|---|---|
| 浏览器 `localStorage` | 不采用为主存储 | 只对当前站点和浏览器有效，换浏览器或清理站点数据后会丢失，无法安全扫描和打开本地成果 |
| 本地 JSON 任务库 | 采用 | 与现有 `127.0.0.1:8768` 报告桥共用安全边界，可长期保存、扫描成果并调用访达 |
| 云端数据库 | 暂不采用 | 会增加账号体系、同步冲突和本地路径隐私风险，本期投入产出不合理 |

## 3. 用户流程

### 3.1 创建任务

用户粘贴链接并点击“抓取并分析”后：

1. 前端识别平台和目标 Skill。
2. 生成稳定任务 ID。
3. 通过本地报告桥写入任务记录，初始状态为“等待中”。
4. 任务列表立即可见该任务的链接、平台、Skill 和创建时间。
5. 前端开始连接平台采集桥，并把状态更新为“进行中”。

如果本地任务记录服务不可用，页面明确提示“无法创建可追踪任务”，不静默产生一份任务列表无法找到的抓取结果。

### 3.2 运行与失败

任务进度与页面四阶段保持一致：

| 阶段 | 状态 | 进度 |
|---|---|---:|
| 已识别平台，等待连接 | waiting | 10% |
| 正在连接本地 Skill | running | 25% |
| 正在抓取平台数据 | running | 60% |
| 正在登记成果 | running | 90% |
| 成果已登记 | completed | 100% |

连接或抓取失败时，任务状态改为 `failed`，保留安全化错误摘要和更新时间。不得在错误记录中写入 Cookie、Token、响应正文或用户登录态信息。

### 3.3 完成与跳转

抓取成功后：

1. 前端把平台采集桥返回的 `outputDir`、`excelPath` 等信息交给本地报告桥。
2. 报告桥在受控输出根目录内扫描本次成果并建立清单。
3. 任务更新为“已完成”。
4. 工作台自动切换到“成果文件”标签。
5. 成果页只聚焦本次任务，同时保留切换到全部历史成果的入口。

自动切换只发生在任务成功且成果登记完成之后；失败任务继续留在当前页面展示错误，不跳到空成果页。

## 4. 持久化数据

### 4.1 存储位置

任务库保存在：

```text
outputs/competitor-insight/.workbench/project-records.json
```

该目录已被 Git 忽略，只存在用户本机，不进入代码仓库或 Sites 发布包。

写入采用“临时文件 + 原子替换”，避免进程中断产生半份 JSON。记录文件包含 `schemaVersion`，为后续迁移保留兼容入口。

### 4.2 任务记录

每条竞品抓取任务至少包含：

- `id`
- `agentId`
- `title`
- `platformId` 与平台名称
- `skillId`
- `sourceUrl`：清理敏感查询参数后的公开链接
- `status`
- `progress`
- `currentStep`
- `createdAt`、`updatedAt`、`completedAt`
- `errorSummary`
- `artifactIds`

小红书链接中的 `xsec_token`、`token`、签名和来源追踪参数不得写入任务库。界面展示可识别作品或账号的规范化公开链接，不展示临时访问凭据。

### 4.3 成果记录

每项成果至少包含：

- `id`
- `taskId`
- `kind`：`excel`、`markdown`、`json`、`image-directory` 或 `output-directory`
- `name`
- `absolutePath`
- `sizeBytes`：目录允许为空
- `createdAt`
- `previewable`

成果记录只保存文件元数据和路径，不复制文件正文。用户移动或删除文件后，成果页显示“文件已不存在”，但保留历史任务记录。

## 5. 本地桥接口

在现有 `127.0.0.1:8768` 报告桥增加以下能力：

| 方法与路径 | 用途 |
|---|---|
| `GET /project-records?agentId=competitor-insight` | 读取任务和成果 |
| `POST /project-tasks` | 创建任务 |
| `PATCH /project-tasks/{taskId}` | 更新状态、进度和错误摘要 |
| `POST /project-tasks/{taskId}/artifacts` | 扫描并登记本次成果 |
| `POST /project-artifacts/{artifactId}/reveal` | 在访达中显示已登记成果 |

接口继续复用当前正式 Sites Origin 和本地开发 Origin 白名单。写接口拒绝空 Origin、非白名单 Origin 和超限请求体。

## 6. 成果扫描与访达安全

允许扫描和打开的根目录仅包括：

- `outputs/competitor-insight/douyin/`
- `outputs/competitor-insight/xiaohongshu/`
- `outputs/competitor-insight/reports/`

安全规则：

1. 所有路径先解析为绝对真实路径。
2. 拒绝 `..`、符号链接逃逸和不在允许根目录内的路径。
3. `reveal` 接口只接收成果 ID，不接受网页直接提交任意文件路径。
4. 文件使用 macOS `open -R -- <path>` 在访达中选中；目录使用 `open -- <path>` 打开。
5. 子进程调用使用参数数组，不拼接 Shell 命令。
6. 文件不存在时返回明确错误，不尝试创建、移动或恢复文件。

## 7. 页面改造

### 7.1 任务列表

竞品洞察 Agent 的任务卡新增：

- 平台标识。
- 抓取 Skill。
- 清理后的项目链接，可点击在新标签打开。
- 当前抓取步骤和进度。
- 完成后的“查看成果”入口。

原有演示任务与真实持久化任务由同一查询层合并；真实任务按更新时间倒序展示。其他 Agent 的静态演示数据不受影响。

### 7.2 成果文件

竞品洞察 Agent 的成果页从“只显示 Markdown”扩展为分类成果列表：

- Excel 数据文件。
- Markdown 分析报告。
- JSON 原始数据或证据包。
- 图片目录。
- 完整输出目录。

操作规则：

- 所有成果支持“复制路径”。
- 所有仍存在的成果支持“在访达中显示”。
- Markdown 延续现有只读预览、复制内容和下载能力。
- Excel、JSON 和图片目录本期不在网页内编辑。

### 7.3 自动跳转

`CompetitorInsightPanel` 完成成果登记后，把 `taskId` 和成果清单上报给 `AgentWorkspace`。工作区随后：

1. 刷新持久化任务和成果状态。
2. 设置当前成果任务 ID。
3. 把活动标签切换为“成果文件”。

刷新页面后默认仍进入项目总览，不自动重复跳转；历史成果通过任务列表或成果文件页主动查看。

## 8. 兼容与异常处理

- 现有静态 `PROJECT_TASKS` 和 `PROJECT_RESULTS` 保留，作为演示数据与无本地桥环境的只读基线。
- 竞品真实任务使用独立 ID 前缀，避免与演示任务冲突。
- 本地任务库不存在时自动初始化为空库，不把初始化错误伪装成“没有任务”。
- JSON 损坏时保留原文件副本并返回错误，不覆盖为新空库。
- 抓取成功但成果扫描失败时，任务标记为失败并提示“文件已生成，但成果登记失败”，同时保留输出目录文字，避免误导用户重复抓取。
- 单作品抓取同样登记成果；是否继续生成账号报告仍沿用现有业务规则。

## 9. 测试策略

按测试驱动开发执行：

1. 记录库单元测试：创建、更新、原子写入、损坏 JSON、敏感参数清理。
2. 路径安全测试：允许目录、越界路径、符号链接逃逸、缺失文件。
3. 桥路由测试：Origin 白名单、请求校验、任务读写、成果扫描、访达接口只接收成果 ID。
4. 前端组件测试：任务链接展示、多类型成果展示、复制路径和文件缺失状态。
5. 工作区集成测试：抓取成功后自动切换成果页并聚焦本次任务；失败时不跳转。
6. 浏览器验收：用真实公开链接完成一次抓取，验证任务持久化、成果清单、刷新恢复和访达按钮。

真实验收不读取、导出或记录 Cookie，也不执行点赞、评论、关注或发布。

## 10. 验收标准

- 点击抓取后，链接立即出现在竞品洞察 Agent 的任务列表。
- 任务状态和进度与实际抓取阶段一致。
- 刷新网页及重新打开浏览器后，任务和成果仍存在。
- 抓取成功后自动切换到“成果文件”并聚焦本次任务。
- Excel、Markdown、JSON、图片目录和完整输出目录能够按实际产出展示。
- “复制路径”复制绝对路径；“在访达中显示”能够定位已登记且仍存在的成果。
- 任意路径、越权 Origin、敏感链接参数和不存在文件均被安全处理。
- 抖音、小红书现有抓取能力及抖音账号报告流程不回归。
- 全量自动化测试、正式站浏览器调用链和本机服务健康检查通过后才允许发布。

# 竞品洞察 Agent 证据型账号报告升级设计

- 日期：2026-07-31
- 状态：已完成方案确认，等待书面设计审阅
- 适用范围：AI 综合工作台的竞品洞察 Agent
- 首期平台：抖音账号 Excel

## 1. 目标

把竞品洞察 Agent 从“识别链接并调用抓取 Skill”升级为完整闭环：

1. 粘贴抖音账号链接后，调用 `douyin-scraper` 生成 Excel，并自动进入分析。
2. 支持用户直接选择已有抖音账号 `.xlsx` 文件，跳过抓取进入分析。
3. 使用确定性程序完成字段识别、数据清洗、排序、指标计算和证据组织。
4. 使用竞品洞察 Agent 已配置的文案模型，只基于证据包生成分析判断。
5. 按固定结构生成 Markdown 报告，完成校验后保存、预览和下载。

成功标准不是“生成一篇看起来完整的报告”，而是关键数字可复算、关键结论可追溯、数据不足不脑补、医药健康内容不被改写成违规营销结论。

## 2. 本期范围

### 2.1 包含

- 抖音账号 Excel 自动分析。
- 抓取后自动分析和已有 Excel 分析两个入口。
- 账号概览、战略层、业务层、内容层、流量层、数据层、对标建议和 7 天执行清单。
- Top 10、起号期 Top 5、高收藏 Top 5、高分享 Top 5、高评论 Top 5。
- 数据完整性检查、弱判断、待验证假设和证据引用。
- Markdown 报告与结构化证据包本地保存。
- 报告在线预览、下载、失败章节重试和校验状态展示。

### 2.2 不包含

- 不在本期为小红书复用抖音字段和报告模板。
- 不分析 Excel 未提供的评论正文、视频画面、商品、直播、私域或成交数据。
- 不建立数据库任务持久化、多人协作或云端文件存储。
- 不修改原始 Excel。
- 不把公开互动数据解释为成交量、销售额或真实转化率。
- 不自动发布、点赞、评论、关注或操作平台账号。

小红书继续保留现有抓取入口；后续应基于小红书字段和内容形态单独设计报告模板。

## 3. 方案选择

采用“确定性数据计算 + 结构化模型洞察 + 确定性 Markdown 渲染”的混合方案。

不采用“把整份 Excel 和全部规则直接交给模型”的方式，因为模型可能错误解析 `1.5w`、改变 Top 排名、遗漏数据缺口或生成无证据建议。

不采用完全固定模板，因为战略、人设、内容模式和可模仿角度需要受控的语义判断。

三层职责如下：

| 层级 | 负责内容 | 不负责内容 |
|---|---|---|
| 数据引擎 | Excel 读取、字段匹配、数值清洗、排序、指标、证据包、固定表格 | 不做账号定位和运营推断 |
| 模型洞察 | 基于证据编号生成结构化判断、建议和脚本骨架 | 不重算数字，不改变排名，不补充 Excel 外事实 |
| 报告渲染器 | 将确定性表格和结构化洞察组装成 Markdown，展开证据详情 | 不自由改写模型结论 |

## 4. 总体架构

```text
抖音账号链接
    ↓
平台路由 → douyin-scraper → Excel 精确路径
                              ↓
已有 Excel 文件 ─────────→ 本地报告桥 127.0.0.1:8768
                              ↓
                    Excel 解析与确定性计算
                              ↓
                 证据包 JSON + 固定 Markdown 片段
                              ↓
              浏览器使用 Agent 已配置文案模型分批生成
                              ↓
                    结构化章节 JSON 校验
                              ↓
                 确定性 Markdown 组装与合规检查
                              ↓
              reports/*.md + evidence/*.json
```

### 4.1 边界

- `douyin-scraper` 继续只负责抓取和 Excel 导出，不承担二次报告生成。
- 新增项目内的竞品报告运行时，源代码放在 `agents/competitor-insight/runtime/`。
- 报告规则以 `agents/competitor-insight/reporting/report-policy.md` 和结构化响应 Schema 版本化保存；用户确认的 656 行提示词是首版规则来源。
- Python 独立环境放在 `agents/competitor-insight/.venv/`，加入忽略规则，不提交依赖目录。
- 本地报告桥只监听 `127.0.0.1:8768`；`8767` 由无关本地服务占用，不停止也不复用。
- 模型凭据只经过现有模型注册表和安全请求链路，不传给 Python、本地报告桥、Excel 或证据包。

## 5. 界面设计

竞品洞察 Agent 的“Agent 对话”页保留平台识别能力，并增加两个一级入口。

### 5.1 抓取并分析

用户粘贴抖音账号链接后：

1. 识别为抖音。
2. 调用 `douyin-scraper`。
3. 采集桥返回本次生成的精确 Excel 路径。
4. 自动调用报告桥分析该路径。
5. 数据计算完成后，调用竞品洞察 Agent 当前选定模型生成报告。

抖音单作品链接继续走单作品抓取，不触发账号报告模板。系统必须依据抓取返回的 `input_type` 或 Excel 工作表结构确认这是账号数据。

### 5.2 分析已有 Excel

用户通过文件选择器选择 `.xlsx`：

1. 浏览器读取文件字节，不依赖浏览器暴露本机真实路径。
2. 将文件字节发送给本机报告桥。
3. 报告桥校验扩展名、ZIP/XLSX 文件签名、大小和工作表结构。
4. 文件副本仅保存到本次任务的受控临时目录，证据包生成后删除临时副本；原始用户文件始终不变。

### 5.3 状态与操作

界面展示五个真实阶段：

1. 读取 Excel
2. 清洗和计算
3. 生成证据包
4. 分章节生成报告
5. 校验并保存

完成后展示：

- 报告文件名与绝对路径
- 数据完整性摘要
- 报告校验结果
- Markdown 预览
- 下载报告
- 复制本地文件路径
- 仅重试失败章节

未配置已连接文案模型时，允许完成前三个阶段，但第四阶段暂停，并提供前往“Agent 配置”的明确提示。

## 6. 本地报告桥

### 6.1 端点

| 端点 | 用途 |
|---|---|
| `GET /health` | 返回服务状态和受控输出目录 |
| `POST /analyze-path` | 分析本次抖音抓取目录中的精确 Excel 路径 |
| `POST /analyze-upload` | 接收已有 `.xlsx` 文件字节并分析 |
| `POST /validate-section` | 使用证据包校验一批模型章节 JSON |
| `POST /assemble-report` | 组装、终检并保存 Markdown |

### 6.2 安全要求

- 只绑定 `127.0.0.1`。
- 只允许 `http://localhost:3000` 和 `http://127.0.0.1:3000`。
- 上传大小默认上限 50 MB。
- `analyze-path` 只接受解析后位于 `outputs/competitor-insight/douyin/` 的 `.xlsx`。
- 禁止 `..`、符号链接逃逸和任意输出路径。
- 输出文件名由账号昵称经过安全清洗后生成，不接受用户提供的目标路径。
- 不记录文件正文、模型凭据、Cookie、Token 或完整模型响应。

## 7. Excel 解析与字段识别

### 7.1 工作表优先级

按以下顺序匹配：

1. `账号概览`
2. `全部作品`
3. `分析摘要` 或 `数据摘要`

名称不同则依据表头语义匹配。至少必须找到一个账号信息表和一个包含作品标题的作品表；找不到作品表或作品数为 0 时停止。

### 7.2 字段同义词

| 标准字段 | 可接受字段 |
|---|---|
| 标题 | 标题、文案、作品标题、desc |
| 点赞 | 点赞、点赞数、likes |
| 评论 | 评论、评论数、comments |
| 收藏 | 收藏、收藏数、collects |
| 分享 | 分享、分享数、shares |
| 发布时间 | 发布时间、发布时间戳、publish_time、create_time |
| 视频链接 | 视频链接、链接、url |

字段匹配记录原字段名和匹配置信度。标题字段缺失时停止；互动字段缺失时按 0 计算并写入数据完整性说明。

### 7.3 数值清洗

- `1.5w`、`1.5W`、`1.5万` → `15000`
- `8000` → `8000`
- `0`、空值、缺失值、无法识别值 → `0`
- 去除逗号、空格和常见展示后缀后再解析
- 负数视为异常并按 0 处理，同时记录警告

综合互动量固定为：

```text
点赞数 + 评论数 + 收藏数 + 分享数
```

## 8. 排名与指标口径

### 8.1 通用并列规则

所有榜单先按目标指标降序，再按发布时间降序，最后按 Excel 原始行号升序。该规则确保同一份 Excel 多次运行结果一致。

### 8.2 Top 10

- 按综合互动量降序。
- 作品不足 10 条时列出全部。

### 8.3 起号期 Top 5

- 作品数不少于 20：按发布时间升序后，取 `ceil(总作品数 × 25%)`。
- 作品数不足 20：取最早 5 条。
- 缺少发布时间的作品不参加起号期筛选。
- 计算全部作品平均综合互动量。
- 起号期中优先选择超过全账号平均综合互动量 2 倍的作品。
- 不足 5 条时按起号期综合互动量补足。

### 8.4 其他榜单

- 高收藏 Top 5：按收藏数。
- 高分享 Top 5：按分享数。
- 高评论 Top 5：按评论数。
- 对应字段整体缺失时不生成该榜单，并说明无法判断。

### 8.5 数据摘要

确定性计算：

- 作品总数
- 平均点赞
- 平均评论
- 平均收藏
- 平均分享
- 平均综合互动量
- 最高综合互动量
- 高于平均综合互动量作品数
- Top 10 综合互动量占比
- 最高作品相对平均值倍数

Top 10 占比公式：

```text
Top 10 综合互动量之和 ÷ 全部作品综合互动量之和
```

分母为 0 时显示“无法计算”，不输出 0% 或无穷值。

## 9. 证据包

每条作品生成稳定证据编号，如 `DY-E0001`。证据对象至少包含：

```json
{
  "evidenceId": "DY-E0001",
  "sourceRow": 12,
  "title": "作品标题",
  "likes": 12000,
  "comments": 320,
  "collects": 860,
  "shares": 210,
  "totalInteractions": 13390,
  "publishedAt": "2026-07-01 10:00:00",
  "url": "https://www.douyin.com/video/...",
  "ranks": {
    "overall": 1,
    "startup": null,
    "collect": 2,
    "share": 4,
    "comment": 1
  }
}
```

证据包还包含：

- 账号基础信息
- 原字段映射
- 缺失字段
- 数据警告
- 汇总指标
- 各榜单证据编号
- 固定 Markdown 表格片段
- 抓取或上传来源
- 分析时间

证据包保存到：

```text
outputs/competitor-insight/reports/evidence/[账号昵称]_证据包.json
```

## 10. 模型生成

### 10.1 调用方式

使用竞品洞察 Agent 在“Agent 配置”中选择的已连接文案模型：

- 通过 `useModelRegistry()` 获取 Agent 模型选择、连接状态和凭据修订。
- 复用现有官方服务端代理和受控浏览器直连规则。
- 新增竞品报告专用运行时，设置独立的输入、输出、超时和响应大小上限。
- 凭据修订变化、用户停止或组件卸载时立即取消请求并丢弃迟到结果。

### 10.2 分批生成

报告分三批：

1. 战略层、业务层、内容层
2. 流量层、数据层
3. 对标建议、拍法模板、转化假设、7 天执行清单

每批只接收该章节需要的账号信息、汇总指标和证据子集，不传整份 Excel。

第三批必须返回至少 5 个不同的选题方向、至少 3 个绑定具体证据的拍法模板，以及完整 7 天执行清单；证据不足时保留数量要求，但将对应条目标记为待验证假设，不伪造支撑作品。

### 10.3 模型输出协议

模型不直接输出最终 Markdown，而是输出结构化章节 JSON。每条判断包含：

- `statement`
- `strength`：`direct`、`weak` 或 `hypothesis`
- `evidenceIds`
- 对标建议需要的可模仿点、不可照抄点和选题示例

模型不得提供原始数字；报告渲染器根据 `evidenceIds` 注入标题、排名、点赞、评论、收藏、分享、综合互动量和发布时间。

这样可以保证模型不能改变排名、互动数字或证据详情。

## 11. Markdown 报告

最终固定结构：

1. `# 抖音账号分析报告 - @[账号昵称]`
2. 账号概览
3. 战略层：账号定位与人设分析
4. 业务层：转化路径与商业价值分析
5. 内容层：选题策略与爆款内容分析
6. Top 10 高表现作品
7. 起号期 Top 5
8. 高收藏、高分享、高评论作品
9. 流量层：传播与互动表现分析
10. 数据层：关键指标与账号健康度分析
11. 对标建议：拍什么、怎么拍、怎么承接
12. 7 天对标执行清单

确定性渲染器负责所有数字表格。模型段落中的证据编号展开为可见证据，至少包含：

- 作品标题
- 榜单排名
- 点赞数
- 评论数
- 收藏数
- 分享数
- 综合互动量
- 发布时间

输出路径：

```text
outputs/competitor-insight/reports/[账号昵称]_抖音账号分析报告.md
```

同名报告一律增加精确到秒的时间戳，不覆盖历史报告。

## 12. 校验与合规

### 12.1 四层校验

1. 结构校验：固定章节、表格和 7 天清单齐全。
2. 数字校验：报告中的数字来自证据包，固定表格未被改变。
3. 证据校验：结论和建议引用有效证据编号；建议至少引用一条 Top 10 或起号期 Top 5。
4. 合规校验：医疗健康内容不形成诊断、疗效承诺、停换药建议、绝对化表达或虚假权威背书。

### 12.2 推断等级

- `direct`：Excel 字段或指标可直接支持。
- `weak`：只能基于标题、发布时间或互动结构判断，报告显示“基于标题和互动数据的弱判断”。
- `hypothesis`：缺少评论正文、画面、商品、直播、私域或成交数据，报告显示“待验证假设”。

如果模型将弱判断写成确定结论，校验失败并只重试该章节。

### 12.3 医药健康边界

- 可以分析竞品标题使用的内容角度，但不认可或放大其中的医疗结论。
- 不把高互动医疗内容解释为医学正确或疗效有效。
- 对标建议优先转译为健康认知、生活方式、日常管理、就医提醒和合规科普。
- 不建议复制诊断式标题、疗效承诺、恐吓焦虑、停换药或资质不明的医生背书。

## 13. 异常与恢复

| 异常 | 处理 |
|---|---|
| 路径无效或文件损坏 | 停止并说明文件问题 |
| 工作表无法识别 | 显示检测到的工作表，不生成报告 |
| 没有作品数据 | 停止，不调用模型 |
| 关键互动字段缺失 | 按 0 计算并重复提示数据缺口 |
| 发布时间部分缺失 | 缺失作品不参加起号期，其余分析继续 |
| 未配置模型 | 保存证据包，暂停报告阶段 |
| 单批模型超时 | 保留证据包和已完成章节，支持重试该批 |
| 模型响应格式错误 | 安全重试一次，仍失败则标记该批失败 |
| 章节证据校验失败 | 只重试失败章节，不重跑抓取和计算 |
| 最终校验失败 | 保存为未通过草稿，不作为正式报告交付 |

抓取成功但未返回精确 Excel 路径时，只检查本次受控抖音输出目录，不扫描桌面、下载目录、用户主目录或其他项目。

## 14. 测试设计

### 14.1 数据引擎单元测试

- `1.5w`、`1.5W`、`1.5万`、`8000`、逗号数字、空值、异常字符串和负数。
- 工作表精确匹配和语义匹配。
- 字段同义词映射。
- Top 10 和并列排序。
- 起号期 25%、不足 20 条、缺少发布时间和不足 5 条。
- 高收藏、高分享和高评论榜单。
- 均值、最高值、平均值倍数和 Top 10 占比。
- 分母为 0。

### 14.2 证据与渲染测试

- 每条作品证据编号稳定且唯一。
- 固定表格与证据包数字一致。
- 无效证据编号拒绝。
- 每条对标建议至少引用一条 Top 10 或起号期证据。
- `weak` 和 `hypothesis` 标签正确渲染。
- 模型返回的伪造数字不能进入最终报告。
- 同名报告不覆盖。

### 14.3 服务安全测试

- 非本地来源返回 403。
- 非 XLSX、超大文件和错误签名被拒绝。
- 路径穿越、符号链接逃逸和非受控目录被拒绝。
- 错误响应不包含文件正文、模型凭据或内部堆栈。

### 14.4 界面与集成测试

- 抓取成功后自动进入分析。
- 已有 Excel 上传直接进入分析。
- 抖音单作品不触发账号报告。
- 小红书仍走小红书桥，不误用抖音报告。
- 未配置模型时停在证据包阶段。
- 停止、重试失败章节和迟到响应丢弃。
- 报告预览与下载使用完全相同的 Markdown。

### 14.5 工程基线

- 完整构建通过。
- TypeScript 类型检查通过。
- Lint 通过。
- 全量自动化测试通过。
- GitNexus 变更检测仅影响预期的竞品洞察、模型运行时和成果展示流程。

## 15. 完成定义

本功能只有同时满足以下条件才算完成：

1. 两个入口都能产生同一计算口径的证据包。
2. Top 10、起号期 Top 5 和各互动榜单可由测试复算。
3. 报告中的数字无法被模型修改。
4. 每条关键建议都有可见作品证据，或明确标记为待验证假设。
5. 缺少数据时不生成确定结论。
6. 医药健康竞品分析通过合规检查。
7. Markdown 保存、预览、下载一致。
8. 抓取和报告任一阶段失败均不破坏原始 Excel。
9. 现有抖音、小红书路由和抓取能力回归通过。
10. 项目进度文档和 Obsidian 镜像同步更新。

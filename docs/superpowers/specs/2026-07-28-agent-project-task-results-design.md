# AI 综合工作台：Agent 项目任务与成果文件设计

日期：2026-07-28  
状态：用户已确认方案  
适用范围：所有独立 Agent 项目页  
覆盖关系：本设计覆盖 `2026-07-25-multi-agent-workbench-design.md` 中关于“项目资料”“执行过程”“成果交接”和单个 Agent 项目页导航的旧设计。

## 1. 目标

缩减单个 Agent 项目页的功能层级，将任务运行信息集中到“任务列表”，将已经完成的 Markdown 文档集中到“成果文件”。

项目页不再设置“项目资料”“执行过程”和“成果交接”，降低使用复杂度，避免同一任务的信息分散在多个页面。

## 2. 项目页导航

项目页只保留五个选项，并按以下顺序排列：

1. 项目总览
2. Agent 对话
3. 任务列表
4. 成果文件
5. Agent 配置

删除：

- 项目资料
- 执行过程
- 成果交接

被删除的三个选项不保留空白入口、跳转按钮或占位页面。

## 3. 任务列表

任务列表既展示当前任务，也展示历史任务。默认按最新更新时间倒序排列。

每条任务至少显示：

- 任务名称。
- 当前状态。
- 创建时间。
- 最近更新时间或完成时间。
- 使用模型。
- 进度信息。

任务状态包括：

- 等待中。
- 进行中。
- 已完成。
- 失败。
- 已停止。

状态展示规则：

- 等待中的任务显示“等待开始”。
- 进行中的任务显示进度百分比、进度条和当前步骤。
- 已完成任务显示完成时间和“查看成果”入口。
- 失败任务显示简短错误摘要。
- 已停止任务显示停止时间。

列表支持按状态筛选。筛选只影响当前展示，不改变任务数据。

## 4. 成果文件

成果文件只收录已完成任务生成的 `.md` 文档。未完成、失败或已停止的任务不生成成果文件。

每份成果至少显示：

- Markdown 文件名。
- 来源任务。
- 完成时间。
- 文件大小。

支持的操作：

- 查看 Markdown 内容。
- 复制文档内容。
- 下载 `.md` 文件。

不支持：

- 在成果文件页面继续编辑。
- 将未完成内容保存为正式成果。
- 从成果页面发起跨 Agent 交接。

“查看成果”使用只读预览。页面应明确显示该文件是已完成成果，避免用户误认为仍处于编辑状态。

## 5. 任务与成果关联

1. 每个成果文件必须关联一个已完成任务。
2. 一个任务可以没有成果文件，也可以产生一份或多份 Markdown 文档。
3. 从已完成任务点击“查看成果”时，进入该任务关联的成果文件。
4. 从成果文件返回时，保留任务列表原有筛选状态。
5. 删除任务不在当前阶段开放，避免任务记录与成果文件之间出现断链。

## 6. 空状态与异常状态

- 没有任务时，显示“还没有任务，可从 Agent 对话发起”。
- 没有进行中任务但存在历史任务时，继续展示历史记录。
- 没有成果文件时，显示“任务完成后，Markdown 成果会出现在这里”。
- Markdown 内容读取失败时，保留文件记录并显示“暂时无法预览”，仍允许重新尝试下载。

## 7. 验收标准

- 项目页只显示五个确认后的导航选项。
- 页面中不存在“项目资料”“执行过程”“成果交接”入口。
- 任务列表同时展示当前任务和历史任务。
- 进行中任务能够显示当前步骤和进度。
- 已完成任务能够打开关联的 Markdown 成果。
- 成果文件只包含已完成任务的 `.md` 文档。
- Markdown 成果可以查看、复制和下载，但不能编辑。
- 任务筛选、成果跳转和空状态在桌面端及移动端可正常使用。

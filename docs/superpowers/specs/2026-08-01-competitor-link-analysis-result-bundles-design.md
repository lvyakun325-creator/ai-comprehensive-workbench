# 竞品洞察 Agent：单链接分析与成果包设计

- 日期：2026-08-01
- 状态：待用户审阅
- 已选方案：方案一，「一次任务一个成果包卡片，内部文件折叠，支持 ZIP 下载」
- 作用范围：仅竞品洞察 Agent
- 覆盖关系：本设计覆盖旧界面中「分析已有 Excel」第二入口，并将竞品成果页的「每个内部文件一张卡片」替换为「每个任务一个成果包」。其他 Agent 的任务和 Markdown 成果逻辑不变。

## 1. 目标

把竞品洞察 Agent 收口为一条可理解、可追踪、可验证的主流程：

1. 用户只粘贴抖音或小红书链接。
2. 工作台自动识别平台与链接类型，调用对应抓取 Skill。
3. 确定性程序完成数据清洗、排名、均值、占比和起号期筛选。
4. 大模型只读取经验证的证据包，按平台和链接类型使用对应分析合同。
5. 报告经过结构、数字、证据引用和医疗健康合规校验后才能完成。
6. 一次任务在成果页只显示一个成果包卡片。
7. 完整流程成功后自动切换到「成果文件」，并聚焦本次成果包。

## 2. 不在本次范围

- 不再支持用户从浏览器选择或上传 Excel 分析。
- 不让大模型直接计算 Top 10、均值、占比或起号期 Top 5。
- 不把单作品链接伪装成账号报告。
- 不引入云端数据库、跨设备文件同步或多人权限。
- 不读取、导出、展示或记录 Cookie、浏览器 state 或登录凭据。
- 不执行点赞、收藏、关注、评论、私信或发布。
- 不删除现有失败任务和历史成果文件。

## 3. 单入口界面

### 3.1 保留

- 「竞品主页或作品链接」输入框。
- 平台与 Skill 自动识别提示。
- 「抓取并分析」主按钮。
- 真实任务阶段、进度和分层错误提示。

### 3.2 删除

- 「第二入口」标识。
- 「分析已有 Excel」标题和说明。
- 「选择已有 Excel 文件」按钮。
- 文件 input、拖拽、扩展名和 50 MB 校验、浏览器 Base64 上传逻辑。
- 与手动选择 Excel 相关的空态、错误和重试文案。

### 3.3 五阶段进度

| 阶段 | 用户可见状态 | 完成条件 |
|---|---|---|
| 1 | 识别平台 | 平台与链接类型已确定 |
| 2 | 调用抓取 Skill | 本地服务健康，抓取请求已提交 |
| 3 | 整理账号数据 | 抓取完成，证据包和确定性指标已生成 |
| 4 | 生成洞察报告 | 大模型批次生成完成，校验通过 |
| 5 | 整理成果包 | 主报告、内部文件、manifest 和 ZIP 登记成功 |

任务只有在第 5 阶段完成后才进入 `completed`。抓取完成但模型未配置时，任务保持 `running`，当前步骤显示「证据包已生成，等待配置模型」，不生成空成果包，不自动跳转。

## 4. 平台与链接类型路由

| 平台 | 链接类型 | 抓取能力 | 报告类型 | 成果分类 |
|---|---|---|---|---|
| 抖音 | 账号主页 | `douyin-scraper` 账号模式 | 抖音账号分析报告 | 抖音账号 |
| 抖音 | 单作品 | `douyin-scraper` 作品模式 | 抖音单作品分析报告 | 抖音作品 |
| 小红书 | 账号主页 | `xiaohongshu-scraper` 账号模式 | 小红书账号分析报告 | 小红书账号 |
| 小红书 | 单篇笔记 | `xiaohongshu-scraper` 笔记模式 | 小红书单篇笔记分析报告 | 小红书笔记 |

账号链接只有在抓取结果包含账号身份与作品列表时，才进入账号报告流程。没有作品数据、不能可靠识别账号身份或链接类型与抓取结果不一致时，任务失败关闭，不交给模型猜测。

## 5. 数据与模型分工

### 5.1 抓取 Skill

- 负责获取平台公开账号信息、作品列表和已支持互动字段。
- 可以继续产生 Excel、JSON、Markdown 和图片作为内部成果，但这些文件不再作为用户的第二入口。
- 抓取成功响应必须返回已校验的结构化结果路径或受控输出目录。

### 5.2 确定性分析器

账号分析器必须在调用大模型之前完成：

- 作品总数和有效数据行数。
- 点赞、评论、收藏、分享字段语义匹配。
- `w`、`万`、数字字符串、空值和不可识别值的统一数字化。
- `综合互动量 = 点赞 + 评论 + 收藏 + 分享`。
- 按综合互动量的全账号 Top 10。
- 按用户规则计算的起号期 Top 5。
- 高收藏、高分享、高评论 Top 5。
- 平均点赞、评论、收藏、分享和平均综合互动量。
- 最高综合互动量、高于均值作品数、Top 10 综合互动量占比。
- 缺失互动字段、缺失发布时间和不参与起号期判断的作品清单。
- 每条证据作品的稳定证据 ID、标题、排名、四项互动、综合互动量、发布时间和链接。

确定性分析器的输出是唯一允许进入模型的数字事实层。模型不能重新排名、替换作品或改写指标。

### 5.3 大模型

- 只基于账号概览、全部作品摘要、确定性指标和证据作品生成分析。
- 不得补全 Excel/JSON 中没有的评论正文、视频画面、商品、直播、店铺、落地页和私域入口。
- 基于标题、发布时间和互动结构的推断必须显式标记「基于标题和互动数据的弱判断」。
- 无法从证据得到的建议必须标记「待验证假设」。
- 医疗健康账号分析不得生成诊断、疗效承诺、停换药建议、绝对化宣称或虚假权威背书。

## 6. 报告合同

### 6.1 抖音账号报告

抖音账号链接使用用户确认的完整证据提示词，报告主结构固定为：

1. `# 抖音账号分析报告 - @[账号昵称]`
2. `## 账号概览`
3. `## 一、战略层：账号定位与人设分析`
4. `## 二、业务层：转化路径与商业价值分析`
5. `## 三、内容层：选题策略与爆款内容分析`
6. `### 3.1 Top 10 高表现作品`
7. `### 3.2 起号期 Top 5 作品`
8. `### 3.3 高收藏 / 高分享 / 高评论作品观察`
9. `## 四、流量层：传播与互动表现分析`
10. `## 五、数据层：关键指标与账号健康度分析`
11. `## 对标建议`
12. `### 第一步：拍什么`
13. `### 第二步：怎么拍`
14. `### 第三步：怎么承接转化`
15. `### 对标执行清单`

强制证据要求：

- 每个结论性判断必须紧邻数据或作品依据。
- Top 10 共性每条至少引用 2 条作品。
- 每个对标选题、拍法模板和执行清单动作至少引用 1 条 Top 10 或起号期 Top 5 作品。
- 作品引用必须包含标题、排名、点赞、评论、收藏、分享、综合互动量和发布时间。
- 「拍什么」至少 5 个不重复的选题方向。
- 「怎么拍」至少 3 个与具体作品绑定的拍法模板。
- 「怎么承接转化」必须分为「数据直接支持」和「待验证假设」。
- 必须包含 7 天对标执行清单，每天 1–2 个动作。
- 作品不足 10 条或起号期不足 5 条时，按确定性结果全部列出，不补造。

### 6.2 小红书账号报告

小红书账号报告沿用相同的证据原则、指标计算和对标结构，但名称使用「笔记」和小红书实际字段。某个字段平台或抓取结果未提供时，必须在数据完整性、对应榜单和相关分析中重复提醒，不使用其他平台字段猜测。

### 6.3 单作品/单笔记报告

单条内容报告只分析当前作品、作者公开信息、互动结构、可获取正文/转写和素材。不生成 Top 10、起号期 Top 5、账号稳定性、账号整体定位和 Top 10 占比。缺少正文、画面或评论正文时，对应部分明确标注数据不足。

## 7. 报告生成与校验

账号报告继续采用分批模型生成，避免单次输出过长导致结构丢失。推荐批次：

1. `strategy`：账号概览、战略层、业务层。
2. `performance`：内容层、Top 10、起号期、高收藏/分享/评论、流量层和数据层。
3. `execution`：对标选题、拍法、转化承接和 7 天清单。

每批必须通过 Schema 校验和证据 ID 引用校验。组装后再执行全报告校验：

- 标题和章节完整、顺序唯一。
- 表格行数、排名和综合互动量与确定性证据一致。
- 报告内数字均能在证据包中找到。
- 证据作品引用字段完整。
- 5 个选题方向、3 个拍法模板和 7 天清单达到最低数量。
- 不得出现证据外的评论内容、画面结构、转化链路或医疗结论。
- 「弱判断」和「待验证假设」标记满足要求。

单批格式或证据校验失败时只允许安全自动重试该批一次。第二次仍失败时任务进入 `failed`，保留已生成证据包供排查，不生成「已完成」成果包。

## 8. 成果包

### 8.1 用户可见定义

成果页的一个列表项代表一次完整任务，不代表某个物理文件。每个完成任务最多一个成果包。

成果包卡片显示：

- 成果包名称。
- 平台分类和账号/作品类型。
- 账号昵称或作品/笔记标题。
- 脱敏后的来源链接。
- 作品数量（账号包）。
- 生成时间、主报告名称和文件完整性。

默认操作：

- `查看分析报告`：直接预览主 Markdown。
- `下载成果包`：下载由本地桥安全提供的 ZIP。
- `在访达中显示`：打开成果包根目录。
- `展开明细`：在当前卡片下方展示内部文件，默认收起。

### 8.2 成果包命名

```text
抖音账号分析｜账号昵称｜2026-08-01
抖音作品分析｜作品标题｜2026-08-01
小红书账号分析｜账号昵称｜2026-08-01
小红书笔记分析｜笔记标题｜2026-08-01
```

同一账号多次生成不覆盖，使用任务 ID 保证目录和成果包唯一，页面按时间倒序。

### 8.3 内部文件

成果包根目录可包含：

```text
主分析报告.md
原始数据.xlsx
结构化数据.json
确定性证据.json
图片素材/
成果包清单.json
成果包.zip
```

对新任务，「主分析报告.md」「成果包清单.json」和「成果包.zip」是完成成果包的强制文件；三者任一缺失，任务都不能进入 `completed`。其他文件根据平台和抓取 Skill 的实际输出登记，缺失时在 manifest 中记录，不创建空占位文件。历史 `legacy` 成果包沿用首次下载时延迟生成 ZIP 的迁移策略。

ZIP 由服务端使用 manifest 的文件白名单生成，禁止符号链接、路径穿越、不在成果根目录内的文件和 Cookie/state 文件。

### 8.4 成果包数据模型

```text
ProjectBundle
- id
- agentId
- taskId
- platformId
- platformLabel
- inputKind                 # account | content
- category                  # douyin-account | douyin-content | xhs-account | xhs-note
- title
- subjectName
- sourceUrl                 # 脱敏后
- status                    # ready | missing | legacy
- primaryArtifactId
- manifestPath
- archivePath
- rootDirectory
- artifactIds
- itemCount
- createdAt
- completedAt
```

`ProjectArtifact` 继续作为成果包子记录存在，但不再直接进入成果页顶层列表。

## 9. 成果页分类和自动跳转

### 9.1 分类

成果页顶部提供：

- 全部成果
- 抖音账号
- 抖音作品
- 小红书账号
- 小红书笔记

失败任务不是成果，只在「任务列表」的失败筛选中展示，不在成果页增加「生成失败」分类。

### 9.2 自动跳转

完成第 5 阶段后：

1. 服务端返回已就绪的 bundle ID。
2. 工作台重新读取本地任务与成果包快照。
3. 确认任务为 `completed`、成果包为 `ready`、主报告存在。
4. 活动标签切换到「成果文件」。
5. 成果页仅显示当前 bundle，显示「正在查看本次成果」。
6. 用户点击「查看全部成果」后才恢复当前分类的历史列表。

页面刷新后不重复自动弹出报告，但历史成果包持续存在，可通过成果页或任务列表打开。

## 10. 本地桥接接口

| 接口 | 作用 | 界面可见性 |
|---|---|---|
| `GET /project-records?agentId=competitor-insight` | 读取任务、成果包和子成果摘要 | 成果页/任务页 |
| `POST /project-tasks` | 链接校验后创建任务 | 主入口 |
| `PATCH /project-tasks/{taskId}` | 更新阶段、进度和错误 | 主入口 |
| `POST /project-tasks/{taskId}/artifacts` | 内部登记抓取和报告文件 | 不直接展示 |
| `POST /project-tasks/{taskId}/bundle` | 校验、生成 manifest/ZIP 并封装成果包 | 流程最后一步 |
| `GET /project-bundles/{bundleId}` | 按需读取成果包明细 | 展开明细 |
| `GET /project-bundles/{bundleId}/download` | 下载已登记 ZIP | 下载成果包 |
| `POST /project-bundles/{bundleId}/reveal` | 在访达中显示成果根目录 | 访达定位 |

原 `POST /analyze-upload` 从白名单和路由分发中移除，返回 404。内部 `analyze-path` 可保留为抓取后账号报告的受控实现细节，但不再对用户提供手动路径入口。

## 11. 历史数据迁移

本地记录从 schema v1 升级为 v2。

- 按 `taskId` 将现有成果分组。
- 一个已完成任务的多个 Excel/Markdown/JSON/目录记录合成一个 `legacy` 成果包。
- 既有物理文件不移动、不重命名、不删除。
- 有 Markdown 时将其设为主报告；没有 Markdown 时保留成果包，但卡片明确显示「无可预览分析报告」。
- 历史成果包的 ZIP 在用户首次点击下载时按白名单延迟生成，避免升级时批量复制大文件。
- 失败任务不创建成果包。
- 迁移使用临时文件、`fsync` 和原子替换；迁移失败时保留 v1 原文件，不静默覆盖。

## 12. 错误处理

| 场景 | 任务状态 | 用户提示 | 成果包 |
|---|---|---|---|
| 不支持的链接 | 不创建 | 请粘贴抖音或小红书主页/作品链接 | 无 |
| 本地 Skill 不可达 | `failed` | 无法连接对应平台抓取服务 | 无 |
| 平台验证/抓取失败 | `failed` | 请在本机完成平台验证后重试 | 无 |
| 账号没有作品数据 | `failed` | 未获取可用作品数据，未生成报告 | 无 |
| 模型未配置 | `running` | 证据包已生成，等待配置模型 | 无 |
| 模型超时/运营错误 | `failed` | 保留安全错误分类，不展示供应商正文 | 无 |
| 报告证据或结构校验失败 | `failed` | 报告未通过证据校验 | 无 |
| ZIP 生成失败 | `failed` | 成果包封装失败，内部文件已保留 | 无完成包 |
| 历史子文件被移动/删除 | 原任务不变 | 成果包不完整，列出缺失项 | `missing` |

失败任务在任务列表提供「重试」，重试创建新任务 ID，保留原失败记录供追溯。

## 13. 安全边界

- 任务源链接持久化前移除 token、source、签名和追踪参数。
- 本地桥仅监听 `127.0.0.1`，写操作、下载和访达定位继续使用精确 Origin 白名单和私有网络预检。
- 任务、bundle 和 artifact ID 都使用严格格式校验，浏览器不能向访达定位或下载接口传入任意本地路径。
- 成果根目录继续限制在 `outputs/competitor-insight/douyin`、`xiaohongshu` 和 `reports`。
- 成果登记、manifest、ZIP、下载和访达定位全部拒绝符号链接和解析后越界路径。
- ZIP 存档名使用服务端生成的安全相对路径，不使用文件系统绝对路径。
- API Key 不进入抓取 Skill、Python 证据包、本地任务记录、manifest、ZIP、Markdown 或日志。
- 平台内容和报告证据作为不可信数据，不能改写模型系统规则、调用方式和证据合同。

## 14. 测试和验收

### 14.1 确定性数据测试

- `1.5w`、`1.5万`、整数、0、空值和非法字符串的转换。
- 缺少收藏/分享字段时按0计算并记录完整性。
- Top 10 只按综合互动量排序。
- 不足 10 条作品时列出全部。
- 起号期前 25%、少于 20 条时的最早 5 条、2 倍均值优先和补齐规则。
- 缺少发布时间的作品不参与起号期。
- 高收藏、高分享、高评论独立排名。

### 14.2 报告合同测试

- 固定章节顺序、表头和数据摘要完整。
- 证据作品八项引用字段完整。
- Top 10 共性的至少两条作品证据。
- 5 个选题方向、3 个拍法模板和 7 天执行清单数量。
- 每条对标建议引用 Top 10 或起号期 Top 5。
- 缺少评论正文、画面、商品和私域数据时的禁止性断言。
- 弱判断、待验证假设和医疗健康合规标记。

### 14.3 成果包测试

- 一个完成任务只生成一个 bundle 记录和一张顶层卡片。
- 子成果默认不出现在顶层列表，展开后才出现。
- 分类筛选不丢任务、不跨平台混入。
- 主报告可预览，ZIP 可下载，访达只打开已登记根目录。
- ZIP 不包含绝对路径、Cookie/state、符号链接和未登记文件。
- 子文件丢失时成果包显示 `missing`，不误报完整。
- v1 多成果记录迁移为一个 legacy bundle，原文件不改动。

### 14.4 界面流程测试

- 竞品采集页不再渲染第二入口和 Excel file input。
- 抖音/小红书、账号/单作品四种路由使用对应 Skill、报告合同和成果分类。
- 五阶段进度与真实请求状态一致。
- 抓取成功但模型/校验/bundle 失败时不自动跳转。
- 完整成功后自动切换成果页并聚焦当前 bundle。
- 刷新页面可读取历史成果包，但不重复触发自动跳转。

## 15. 验收标准

1. 竞品采集页只有链接入口，不存在 Excel 上传入口。
2. 一条有效平台链接能完成平台识别、Skill 抓取、确定性分析、模型分析、报告校验和成果包封装。
3. 抖音账号报告满足用户确认的完整结构与强制证据规则。
4. 账号 Top 10、起号期 Top 5、三类互动榜和关键均值由程序计算，与报告一致。
5. 单作品和单笔记报告不冒充账号分析。
6. 成果页每次任务只显示一个成果包卡片，子文件默认收起。
7. 成果包可预览主报告、展开明细、在访达显示并下载安全 ZIP。
8. 成果页可按抖音账号、抖音作品、小红书账号、小红书笔记分类。
9. 任务只在主报告与 bundle 均就绪后完成并自动跳转。
10. 历史多文件成果可无损迁移为 legacy bundle，不移动或删除原文件。
11. 所有任务和成果包继续本机长期保留，页面刷新后可读取。
12. 本次不改变其他 Agent 的任务和成果逻辑。

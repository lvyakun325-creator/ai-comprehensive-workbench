# 全局模型真实接入设计

## 1. 目标

把现有仅保存模型名称和标识的“全局模型配置”升级为可真实调用的模型配置中心。

本轮交付范围：

- 文案模型支持配置、保存、测试、启用和真实聊天调用。
- 生图模型支持配置、保存和无生成费用的可用性验证。
- 首页聊天智能体真实调用当前选中的文案模型。
- 内容矩阵 Agent 现有独立会话配置和执行链路保持不变。
- 不新增生图工作台；生图配置作为后续 Agent 可复用的全局能力。

## 2. 已确认方案

采用混合调用方案：

- APINebula 等经过明确允许且已验证适合浏览器直连的服务商，由浏览器直接调用。
- 其他 OpenAI 兼容服务商通过工作台安全代理调用。
- 安全代理只转发当前请求，不持久化 API Key。
- API Key 持久保存在当前浏览器本机，刷新和重启后仍可使用。

不采用全部浏览器直连，因为第三方服务商可能阻止跨域请求。  
不采用全部后端代理，因为这会让每次调用都无差别地经过工作台后端。

## 3. 配置模型

### 3.1 文案模型

每个文案模型包含以下非敏感字段：

- `id`：工作台内部稳定标识。
- `provider`：服务商显示名称。
- `displayName`：模型在工作台中的显示名称。
- `modelId`：服务商接口使用的模型名称。
- `baseUrl`：OpenAI 兼容接口的 Base URL。
- `enabled`：是否启用。
- `isDefault`：是否为默认文案模型。
- `connectionStatus`：`untested`、`testing`、`connected`、`failed` 或 `changed`。
- `testedFingerprint`：最后一次成功测试所对应的非敏感配置指纹。

API Key 不进入上述普通模型对象，而是存入独立、版本化的浏览器密钥存储，以模型 `id` 为索引。

### 3.2 生图模型

本轮只维护一套全局生图配置：

- `baseUrl`
- `modelId`
- `enabled`
- `connectionStatus`
- `testedFingerprint`

生图 API Key 同样存入独立的浏览器密钥存储。

### 3.3 现有数据迁移

现有模型列表继续保留，但没有连接配置的模型迁移后状态为“未配置/未测试”。

现有占位模型 `GPT-5.6` 不再直接出现在可用模型选择器中。只有连接测试成功且处于启用状态的文案模型才可被聊天和普通 Agent 选择。

聊天模型选择与各 Agent 模型选择继续相互隔离。

## 4. API Key 保存规则

- API Key 只保存在当前浏览器本机，不写入 Git、源码、下载文件或普通模型元数据。
- 保存后不把完整 Key 回填到输入框。
- 页面只显示脱敏摘要，例如 `sk-T****K6mf`。
- API Key 输入框留空表示继续使用已保存值。
- 只有主动勾选“清空已保存的 API Key”后保存，才删除已有 Key。
- 新增模型时 API Key、Base URL 和模型名称均为必填。
- 编辑已有模型时，API Key 可留空以保留旧值。
- 自动化测试只使用模拟 Key，不读取或调用用户真实密钥。
- 错误信息、控制台日志和接口响应不得包含完整 API Key。

浏览器本地存储无法抵御已经获得当前网页脚本执行权限的恶意代码。工作台应在界面中说明这一边界，不把“本机保存”描述为硬件级或系统钥匙串级加密。

## 5. 页面设计

“模型配置”页面改为参考图风格的集中设置面板。

### 5.1 页面顶部

- 标题：“模型设置”。
- 说明：“分别填写文案模型和生图模型的 API Key、Base URL、模型名称。”

### 5.2 文案模型区域

文案模型以卡片列表展示。每张卡片提供：

- 服务商
- 模型显示名称
- 文案模型 API Key
- 已保存 Key 的脱敏摘要
- 文案接口地址
- 文案模型名称
- 清空已保存的文案 API Key
- 测试文案模型
- 启用/停用
- 设为默认
- 删除

页面提供“添加文案模型”。新增和编辑使用同一套字段规则。

### 5.3 生图模型区域

生图模型卡片提供：

- 生图模型 API Key
- 已保存 Key 的脱敏摘要
- 生图接口地址
- 生图模型名称
- 清空已保存的 API Key
- 测试生图模型
- 启用/停用

### 5.4 页面操作

- “取消”恢复到本次进入页面时的已保存配置。
- “保存设置”把草稿写入当前浏览器本机。
- 修改 API Key、Base URL 或模型名称后，原连接成功状态立即变为“配置已变更”。
- 未测试或测试失败的配置可以保存，但不能启用或用于模型调用。
- 移动端使用单列布局，主要按钮不横向溢出。

## 6. 连接验证

### 6.1 文案模型

文案模型测试向 `Base URL + /chat/completions` 发送一个固定、极短、无业务数据的探测消息。

成功条件：

- HTTP 请求成功。
- 响应是兼容的聊天完成结构。
- 响应中包含可解析的文本。
- 本次测试对应的 Base URL、模型名称和 Key 版本仍未发生变化。

测试成功后记录非敏感配置指纹，不保存服务商响应正文。

### 6.2 生图模型

生图模型测试调用 `Base URL + /models`，确认接口可访问并且配置的模型名称存在，不发起图片生成，避免测试产生图片费用。

如果服务商不提供兼容的模型列表接口，本轮将其视为无法完成无费用验证，并显示明确提示；不会退化为自动生成图片。

## 7. 混合调用路由

### 7.1 浏览器直连

浏览器直连仅允许显式白名单中的 HTTPS 服务商域名。首个白名单为 APINebula 的精确域名匹配，不允许相似域名、子串匹配、HTTP、localhost、私网地址或重定向。

### 7.2 安全代理

其他 OpenAI 兼容接口使用：

- `POST /api/models/test-text`
- `POST /api/models/test-image`
- `POST /api/models/chat`

代理要求：

- 校验请求体大小、字段长度和协议。
- Base URL 必须是 HTTPS 公网地址。
- 拒绝 localhost、`.local`、字面量私网、链路本地和重定向。
- 使用固定的受支持路径，不允许调用方提供任意下游路径。
- 设置明确超时并支持调用方取消。
- 不记录、持久化或返回 API Key。
- 不把服务商原始响应正文直接返回给浏览器。
- 将认证失败、模型不存在、限流、余额或权限问题、超时和格式错误映射为安全中文错误。

## 8. 首页真实聊天

首页聊天智能体使用当前已选中的、已连接且启用的文案模型。

交互规则：

- 空消息不能发送。
- 发送后立即显示用户消息和加载状态。
- 非流式读取本次模型回复，成功后显示模型回复。
- 每条模型回复显示实际使用的模型名称。
- 保留当前页面会话中最近的有限条消息，向模型发送时使用固定上限，防止上下文无限增长。
- 切换模型不清空当前可见对话；后续回复标注新的模型名称。
- 支持停止当前请求。
- 请求失败后保留用户消息，并提供重新发送。
- 快捷开始按钮把示例文字填入输入框，不再显示“设计预览”提示。

本轮不接入附件、工具和语音输入。

## 9. 状态与错误处理

连接状态：

- 未测试
- 测试中
- 连接成功
- 连接失败
- 配置已变更

安全错误类别：

- API Key 无效
- 模型名称不存在
- 接口地址不可访问
- 服务商限流
- 余额或权限不足
- 请求超时
- 浏览器直连被服务商策略拦截
- 服务商响应格式不兼容

任何错误不得包含完整 Key、服务商原始响应正文或未经脱敏的请求配置。

## 10. 组件与职责边界

- 模型注册表：只负责非敏感模型元数据、启用状态、默认值和选择关系。
- 本地密钥存储：只负责浏览器端 Key 的读取、写入、清空和脱敏摘要。
- 模型连接运行时：负责配置校验、端点拼接、请求构建、响应解析和安全错误映射。
- 模型 API 路由：负责非白名单服务商的安全代理。
- 模型设置页面：只维护表单草稿、测试状态和保存交互。
- 首页聊天组件：只维护当前对话、请求生命周期和模型回复展示。
- 内容矩阵运行时：保持现状，不依赖新的全局模型运行时。

## 11. 验收标准

1. 刷新或重启浏览器后，已保存配置仍然存在。
2. 页面任何位置都不显示完整 API Key。
3. Key 留空可保留旧值，主动勾选后才会清除。
4. 文案模型测试成功后，首页可以发起真实聊天。
5. 修改连接参数后，原测试成功状态立即失效。
6. 未测试、测试失败或停用的模型不出现在模型选择器中。
7. 生图模型可以保存并完成无图片生成费用的连接验证。
8. 接口错误不泄露 API Key 或服务商原始敏感响应。
9. APINebula 直连只接受精确允许的 HTTPS 域名。
10. 其他服务商代理拒绝私网目标和重定向。
11. 现有内容矩阵执行链路和 Agent 项目导航不受影响。
12. 桌面端和移动端均能完成配置、测试、保存和聊天操作。

## 12. 测试范围

- 模型元数据迁移、连接状态和选择回退的单元测试。
- 本地密钥存储的保留、替换、清空、脱敏和损坏数据回退测试。
- Base URL 公网校验、端点拼接、安全错误和 Key 脱敏测试。
- 三个安全代理路由的认证、模型缺失、超时、重定向、私网和超大请求测试。
- APINebula 精确域名直连测试。
- 模型设置页面的新增、编辑、测试、保存、取消和状态失效测试。
- 首页真实聊天的发送、回复、切换模型、停止、失败和重试测试。
- 完整构建、全量测试、ESLint 和差异检查。

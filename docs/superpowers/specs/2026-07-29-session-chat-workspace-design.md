# 本次会话多对话工作区设计

## 目标

把首页现有的单卡片聊天升级为两阶段体验：

1. 用户在首页空态输入第一条问题。
2. 发送后进入独立聊天窗口，在本次打开工作台期间持续多轮对话，并可新建、切换和删除多个会话。

聊天记录只保存在当前页面运行期内存中。切换到模型配置、Agent 项目等工作台页面后仍保留；刷新浏览器、关闭页面或重新打开工作台后清空，不写入 `localStorage`、`sessionStorage`、IndexedDB 或服务端。

## 范围

本轮包含：

- 首页首次输入空态；
- 独立聊天窗口；
- 本次运行期间的多会话内存状态；
- 自动标题、新建、切换和删除；
- 多轮上下文隔离；
- Enter 发送与 Shift+Enter 换行；
- 自动聚焦与自动滚动；
- 请求中、停止、失败和重试状态；
- 桌面端固定历史侧栏与移动端历史抽屉；
- 对应的行为测试、构建、类型和 lint 验证。

本轮不包含：

- 刷新或关闭后保留聊天记录；
- 手动重命名会话；
- 云端同步、分享、导出、搜索或收藏；
- 附件、工具和语音的真实能力接入；
- Markdown 富文本渲染或代码高亮；
- 修改模型配置、API Key 存储和其他 Agent 项目。

## 采用方案

采用顶层内存会话状态方案。

新增一个工作台级 `ChatSessionProvider`，挂在会随着主视图切换而保持存活的顶层位置。`ControlDesk` 只负责聊天界面和用户交互，不再独占会话数据。这样：

- 切换工作台页面时 `ControlDesk` 即使卸载，会话仍保存在 Provider 内；
- 页面刷新会重新创建 Provider，自然清空本次会话历史；
- 会话状态与模型注册表继续分离；
- 不需要把聊天内容写入浏览器存储；
- 后续增加重命名或导出时有清晰扩展点。

不采用“隐藏但不卸载聊天组件”，因为它会把请求生命周期、导航和界面状态耦合在一个长期存活组件中。不采用 `sessionStorage`，因为刷新后仍可能保留内容，而且会增加聊天内容落盘风险。

## 数据模型

### ChatSession

每个会话包含：

- `id`：运行期唯一 ID；
- `title`：首条用户消息生成的标题；
- `messages`：该会话的消息列表；
- `createdAt`：创建时间；
- `updatedAt`：最近一次消息或状态变化时间；
- `draft`：该会话尚未发送的输入草稿；
- `failedRequest`：最近一次可重试失败；
- `pendingRequest`：当前正在运行的请求元数据；
- `scrollOffset`：切换会话或页面时恢复阅读位置所需的滚动信息。

### ChatMessage

每条消息包含：

- `id`；
- `role`：`user` 或 `assistant`；
- `content`；
- `modelName`：助手消息实际使用的显示名称；
- `status`：用户消息的 `sending`、`sent`、`failed` 或 `stopped` 状态；
- `createdAt`。

`modelName` 记录在消息上，避免后续切换模型时改写历史展示。

### Provider API

Provider 对界面暴露：

- `sessions`；
- `activeSessionId`；
- `activeSession`；
- `createSession(firstMessage)`；
- `createEmptySession()`；
- `selectSession(id)`；
- `deleteSession(id)`；
- `updateDraft(id, value)`；
- `appendMessage(id, message)`；
- `updateRequestState(id, patch)`；
- `updateScrollOffset(id, value)`。

Provider 不直接调用模型 API。模型请求仍由聊天控制器发起，Provider 只管理会话状态。

## 会话规则

### 创建与标题

- 首页首次发送时创建新会话，并立即进入独立聊天窗口。
- 标题取首条用户消息去除首尾空白后的前 24 个可见字符。
- 超过 24 个字符时追加省略号。
- 空白内容不能创建会话。
- “发起新对话”创建一个未发送的空会话并聚焦输入框；如果用户未输入就切走，不把该空会话显示在历史列表。

### 切换

- 侧栏按 `updatedAt` 倒序显示非空会话。
- 选中会话后显示其消息、草稿、失败状态和滚动位置。
- 不同会话的消息、草稿、失败状态和请求上下文完全隔离。
- 会话切换不会自动切换全局模型；模型选择继续沿用现有聊天模型选择。

### 删除

- 删除前显示轻量确认。
- 删除非当前会话后保持当前会话不变。
- 删除当前会话后切换到最近更新的剩余会话。
- 删除最后一个会话后返回首页首次输入空态。
- 删除会话时停止并丢弃该会话仍在运行的请求，不接受迟到响应。
- 删除不会修改 API Key、模型配置或其他会话。

## 页面结构

### 首页首次输入空态

保留现有工作台欢迎信息、快捷开始和模型选择，但收紧聊天卡片高度，让输入区有明确边框和操作提示。

空态发送后不在原卡片内堆叠消息，而是切换到独立聊天窗口。

### 独立聊天窗口

桌面端使用两栏结构：

- 左侧：会话历史侧栏；
- 右侧：聊天标题栏、消息滚动区和固定底部输入器。

左侧侧栏包含：

- “发起新对话”；
- “今天”和“更早”分组；
- 自动标题；
- 当前会话选中状态；
- 删除入口；
- 返回工作台其他主导航的入口保持现有结构可达。

右侧顶部包含：

- 当前会话标题；
- 当前选择的模型；
- 移动端历史抽屉入口。

右侧消息区：

- 用户消息为右对齐气泡；
- 助手消息为左对齐正文卡片；
- 长文本保留换行并支持自然滚动；
- 最新消息加入后自动滚到底部；
- 用户主动向上阅读时，不强制抢回滚动位置；只有用户接近底部时才自动跟随。

底部输入器：

- 固定在聊天窗口底部，不随消息增长离开视口；
- 自动伸缩但设最大高度；
- Enter 发送；
- Shift+Enter 换行；
- 发送后清空当前会话草稿、重新聚焦并保持输入器可见；
- 保留模型选择、停止按钮和现有未接入附件/工具/语音提示。

移动端：

- 会话侧栏改为可关闭抽屉；
- 输入器固定在安全区域上方；
- 消息区单独滚动；
- 模型选择菜单不超出视口。

## 请求与上下文数据流

1. 用户在当前会话发送消息。
2. 控制器把用户消息写入当前会话，并记录发送时的模型 ID、显示名称和凭据修订号。
3. 从当前会话提取最近的完整问答，再追加本次用户消息。
4. 不得读取或拼接其他会话消息。
5. 通过现有浏览器直连或安全代理路径调用模型。
6. 响应返回时同时校验：
   - 页面仍挂载；
   - 会话仍存在；
   - 请求 token 仍是该会话当前请求；
   - 模型凭据修订号仍匹配。
7. 通过后把回复追加到原会话，并记录实际模型显示名称。
8. 校验失败或会话已删除时丢弃迟到响应。

上下文继续遵守现有最多 20 个 turn 的限制，只保留完整的用户—助手交换和当前用户消息。

## 连续对话和并发规则

- 同一会话同一时间最多一个模型请求。
- 一个会话请求中时，可以切换到另一个会话查看历史。
- 本轮不支持多个会话同时生成；存在全局活动请求时，其他会话可以编辑草稿，但发送按钮保持不可用，并明确提示哪个会话正在生成。
- 停止请求后保留用户消息，标记为 `stopped`，允许立即继续发送下一条。
- 失败请求不会锁死整个输入器。用户可以：
  - 重新发送失败消息；
  - 编辑并发送新的问题。
- 如果发送新问题，旧失败状态保留在对应消息下方，但不再作为当前阻塞错误。

## 错误与安全

- 继续使用现有安全错误文案，不展示 API Key、上游响应体或内部 URL。
- 错误显示在对应用户消息附近，避免页面级错误条与消息关系不清。
- 重试不重复插入用户消息。
- 使用当前选中的可用模型重试，并在成功回复上记录实际模型。
- 模型被停用、删除或凭据修订变化时停止活动请求，并显示可操作提示。
- 聊天内容只存在 React 运行期内存，不写入日志和浏览器持久化存储。

## 组件边界

### ChatSessionProvider

只负责会话集合、当前会话和会话级状态变更。可单独测试新建、排序、切换、删除、标题和隔离规则。

### ControlDesk

负责首页空态与独立聊天页之间的状态呈现，组合会话侧栏、消息列表和输入器。

### ChatHistorySidebar

负责历史分组、选中、新建和删除确认，不读取模型凭据。

### ChatTranscript

负责消息呈现、请求状态、消息级失败与滚动行为，不发起网络请求。

### ChatComposer

负责草稿、键盘行为、模型选择、发送和停止入口。

### Chat request controller

负责从当前会话生成安全上下文、选择直连或代理、执行请求、校验迟到响应并更新 Provider。

本轮可以先把较小组件保留在同一文件中；如果 `ControlDesk.tsx` 超过可维护范围，则拆成独立组件文件。拆分仅服务本功能，不做无关重构。

## 验收标准

1. 第一条消息从首页进入独立聊天窗口。
2. 同一会话可连续完成至少 3 轮问答，后续请求包含本会话先前完整问答。
3. 新建第二个会话后，上下文不含第一个会话内容。
4. 切换到模型配置或 Agent 项目再返回，两个会话及当前选择仍在。
5. 刷新页面后会话历史为空。
6. 标题由首条问题自动生成并按最近更新时间排序。
7. 可以切换和删除会话，删除最后一个会话返回首页空态。
8. Enter 发送，Shift+Enter 换行。
9. 输入器固定可见，消息增长时只滚动消息区。
10. 新消息在接近底部时自动滚动；向上阅读时不被强制拉回。
11. 停止、失败和重试不会重复用户消息，也不会锁死后续输入。
12. 模型切换后历史回复仍显示其实际模型名称。
13. 移动端历史为抽屉，输入器不被底部安全区域遮挡。
14. API Key 和上游错误详情不出现在 DOM、存储或错误文案中。

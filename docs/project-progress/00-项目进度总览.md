## 项目初衷

建设一个统一的 AI 经营工作台，用一个总控台管理模型、任务、成果和数据，并由 9 个专业 Agent 分工完成内容矩阵、竞品洞察、选题、标题、图文、写作、口播、获客视频和数据复盘。

最终目标不是做一个只有界面的聊天工具，而是形成可连续执行、可追踪进度、可沉淀成果、能提高内容产能与经营决策效率的业务系统。

## 当前结论

当前已经具备较完整的产品界面、模型配置、普通连续聊天、内容矩阵真实执行能力，以及竞品洞察 Agent 的本地双平台采集入口。

本次竞品洞察升级已完成抖音账号证据型报告的本地闭环：支持“抓取并分析”和“分析已有 Excel”双入口；确定性程序负责字段识别、数据清洗、Top 10、起号期 Top 5、互动榜单、汇总指标和证据包；模型按 `strategy / performance / execution` 三批生成结构化判断；最终经过证据、数字、结构和医药健康合规校验后保存 Markdown。官方模型走同源服务端代理，已审核的 APINebula 精确域名可走浏览器直连。

该界面已以 Sites V11 发布到既有生产地址，源码对应 GitHub `main` 提交 `fcde7c6`。发布前将 Next.js 升级到 `16.2.12`，并固定已修复的 PostCSS `8.5.25`、Sharp `0.35.3`；生产依赖审计为 0 个已知漏洞。

## 本地输出与安全边界

- 报告目录：`outputs/competitor-insight/reports/`
- 证据目录：`outputs/competitor-insight/reports/evidence/`
- 抖音抓取输出：`outputs/competitor-insight/douyin/`
- 小红书抓取输出：`outputs/competitor-insight/xiaohongshu/`
- 报告桥只允许受控抖音输出目录中的普通 `.xlsx`，上传上限为 50 MB，并校验 ZIP/XLSX 签名、解压预算、路径穿越和符号链接；所有持久/临时输出基于验证后的目录 fd 创建。
- API Key 不进入 Python、报告桥、Excel、证据包、Markdown、DOM、日志或测试快照。
- 公开互动数据只能用于内容表现判断，不能推断成交量、销售额、真实转化率或医学正确性。
- 医药健康建议不得形成诊断、疗效承诺、停换药建议、绝对化表达或虚假权威背书。
